# Testing

Every layer runs without hardware. Results are labelled `[HOST]` (native build), `[EMU]` (Renode
1.17.0 virtual time) or `[BUILD]`. **Nothing has been validated on a physical board.** The
hardware-in-the-loop layer (PRD §19.5, M9) is specified but not built; see `docs/hardware.md`.

## How to run

```sh
make bootstrap        # once: pinned Arm GCC, Renode, Python venv into ~/.cache/rttelemetry-tools
make test             # host: unit (ASan+UBSan), TSan ring stress, Python tools
make coverage         # src/core line/branch coverage gate (>= 90 % / >= 80 %)
make fuzz             # libFuzzer, 60 s per target (FUZZ_SECONDS=...)
make fw fw-release size-check static-analysis   # firmware builds, memory budgets, no heap, cppcheck
make test-renode      # platform gates + every tests/robot/*.robot suite on Renode
make demo             # scripted end-to-end demo with a live dashboard (~35 s)
make bench-emu soak   # benchmarks -> bench/results, docs/results.md
make ci-docker        # the Linux CI path in ubuntu:24.04 via Docker
```

On macOS 27, Apple clang 15's ASan aborts at startup even for an empty program, so `make test`
builds host tests with Homebrew LLVM there (`HOST_CC`).

## Renode suites

Each test boots `telemetry.elf` with an ADC feed scenario (`renode/data/`, generated by
`tools/gen_feed.py`) and constant IMU input. It captures USART2 to a file and checks the decoded
frames in `tests/robot/TelemetryLibrary.py`. Plausibility flags are checked against an independent
Python oracle, sample by sample.

| ID | Checks | Status |
|---|---|---|
| IT-BOOT-1 | BOOT within 100 ms, version, SHA, reason POWER_ON | pass |
| IT-HEALTH-1 | 5 HEALTH frames 1 000 000 µs ± 1 ms apart (gate G3: tick rate); counters monotonic; stacks > 0 | pass |
| IT-ACQ-1 | 1 kHz × 10 s: seq contiguous, Δt exact, raw values equal feed files, status equals oracle, 0 rejects, exact conservation | pass |
| IT-ACQ-2 | 100/250/500/2000 Hz: Δt and count per rate, 0 overruns | pass |
| IT-ACQ-3 | 100 Hz: partial batches flushed, L1 max ≤ 21 ms | pass |
| IT-CMD-1 | PING, GET_STATUS (HEALTH ≤ 30 ms), SET_RATE invalid → RANGE, RESET_COUNTERS, REBOOT → BOOT reason CMD | pass |
| IT-IMU-1 | IMU at 200 Hz, values exact at ±4 g / 500 dps, ADC path unaffected | pass |
| IT-ACCT-1 | Exact conservation after stop + flush | pass |
| IT-GOLD-1 | Three runs and `tests/golden/nominal.jsonl` byte-identical (output is deterministic, also across Renode processes) | pass |
| FI-01 | Processing stall: ring drops = 300 − 128 ± 10, RING_OVF events, exact conservation | pass |
| FI-02 | Slow link: drops at the frame pool, none at the ring, TXPOOL events | pass |
| FI-03 / FI-04 / roc | RANGE, STUCK onset (sample 449), ROC flags on exactly the expected samples | pass |
| FI-05 | 1000 malformed frames: `rx_frames_bad` = 800 and 200 error ACKs exactly, then PING OK, no reset | pass |
| FI-06 | Hung `cmd_task` → IWDG reset, BOOT reason WDT_TASK_STALL naming `cmd`, samples again ≤ 2 s | pass |
| FI-07 | `UDF` → HardFault, BOOT PC equals the `fi_udf_site` symbol, CFSR = UNDEFINSTR | pass |
| FI-08 | Stack overflow in the sacrificial `fi` task → reason STACK_OVF, task `fi` | pass |
| FI-09 | `configASSERT` → reason ASSERT, file and line match the source | pass |
| FI-10 | Slow DMA ISR → ADC overruns counted, sequence gaps equal the counter | pass |
| FI-12 | I²C NACKs: 2 absorbed by retries; 3 → OFFLINE, recovery, re-probe after 1 s; ADC path 0 drops | pass |

## Emulator caveats that shape the tests

- Timer periods are 1 µs short in Renode (D15). Tests use `${TIM_DT_OFFSET}`.
- The ADC model needs 400 µs per scan (D13), so emulated 4–8 kHz runs overrun by construction. IT-STRESS-1 uses this to drive the overrun path.
- The UART model delivers RX bytes at a finite rate but without baud timing. FI-05 paces its injection accordingly.
- The `Renode reset` macro reloads the ELF on watchdog and software resets. Without it, Renode does nothing on reset.

## Not covered (needs hardware)

Timing and jitter (P-05, P-06), DWT cycle counts (B-03), the real 115200-baud link, bus faults
from wild pointers (D5), DMA-into-CCM silicon behaviour (D4), and the 24 h soak. See `docs/hardware.md`.
